# 计划步骤的离线恢复

2026-10-21，远端 Codex CLI 0.163.0。继续使用官方 app-server；没有新增常驻 Python 服务，也不修改原官方客户端的配置或会话。

## 行为

- 打开已有会话时只读恢复当前回合最新的计划步骤，显示已完成数与每一步状态。
- 无论 Mac 是否在线，远端实际执行 `update_plan` 后都会保存快照。重新打开会读取新状态，不依赖退出前的 Mac 缓存。
- 只读查看期间约每 4 秒检查变化，无需刷新或取得写入权。更新保留输入草稿和已展开的步骤清单。
- 短暂断线后自动退避重试，保留已显示的步骤并注明同步状态；迟到的读取不能覆盖较新的实时通知。
- 切换会话、断开连接或退出会取消本客户端自己的读取。新回合没有计划时清除上一回合清单，避免串用进度。

## 为何需要执行回调

官方 `turn/plan/updated` 是实时通知，0.163.0 不将它直接写入 rollout。直接函数调用的参数与成功结果会保存，可以只读还原；代码模式下，一段 `exec` 脚本可能提前包含多个尚未执行的计划，不能从源码提取最后一份计划并当作完成。

本客户端新建会话启用内置计划工具，并附加官方 `PostToolUse` 回调。它只匹配 `update_plan`：确认工具已成功返回 `Plan updated` 后，将步骤原子保存到远端私有目录。脚本内部调用同样走官方执行回调，模型的工具调用方式保持原样。回调不输出反馈、不批准工具、不改聊天历史、不发送联系人消息。

参考：[官方 Hook 的 PostToolUse 与代码模式行为](https://learn.chatgpt.com/docs/hooks)、[App Server 计划通知](https://learn.chatgpt.com/docs/app-server)。

## 文件与配置边界

- `Resources/plan_recorder.py`：短时执行回调；仅写 `~/.local/state/remote-codex/plan-progress/<thread UUID>.json` 和该线程锁文件。
- 快照目录 0700、文件 0600，锁内写临时文件、fsync 后原子替换。只保存 ID、步骤、说明、回调时间和工具调用 ID。
- 回调源按 SHA256 存放在 `~/.local/share/remote-codex/plan-hooks/<SHA256>.py`；首次新建会话时校验并安装，不覆盖其他文件。没有服务重启。
- Hook 和精确的官方定义哈希通过 `thread/start.config` 的会话参数提供。仅信任该条定义，没有使用绕过 Hook 信任的启动参数，不写全局 `config.toml` 或全局信任状态。
- 本机记住这些新会话的配置，用户主动继续这些会话时恢复同一配置。浏览、刷新和自动同步不会调用 `thread/resume` 或修改已有会话的 Hook。
- `Resources/plan_snapshot.py`：只读投影。先由官方 API 核实 thread ID、rollout 路径和最新 turn ID；有匹配的执行快照时快速返回，否则增量扫描官方日志里的直接调用及成功结果。
- 校验日志首条 `session_meta`，限制目录、文件类型、符号链接与输出大小。只回传计划字段，不把其他聊天正文、思考或工具输出送到 Mac。
- `PlanProgress.swift`：SSH 读取、增量游标、重试、取消和实时通知防回退。读取批次上限 8 MiB/约 0.75 秒，Mac 界面不会同步解析整段历史。

### 旧记录

已有日志中保存的直接调用可以恢复。此前未安装回调、只存在于代码脚本内部且未持久化的执行状态无法追溯；不会把脚本中的未来步骤或普通文字描述冒充已执行计划。保留原会话配置，用户原来正在运行的任务不因此恢复、暂停或重启。
