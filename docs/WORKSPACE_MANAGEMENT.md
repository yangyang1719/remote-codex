# 项目与会话管理

更新：2026-11-09。沿用已批准的 Codex 风格界面。

## 交互

- 左侧“添加远端项目”：填写 SSH 别名、远端绝对目录和可选名称；“目录不存在时创建”默认勾选。经 SSH 创建缺失目录或检查已有目录，成功后才登记并打开项目。路径被文件占用、权限不足或 SSH 失败会留在表单内提示，可修正后重试；不初始化 Git、部署服务或登录账号。相同连接/目录不会重复登记。
- 项目旁的刷新按钮读取当前 SSH 服务上的项目与会话，无需重启。连接后扫描已有根会话的工作目录，自动登记 CLI 创建的新项目；前台约每 15 秒、后台约每 30 秒同步近期会话，回到前台和收到会话创建/改名事件时也会尝试刷新。新发现的项目不会切走当前项目或会话；只创建空目录但尚无会话的目录需手动添加。
- 首次连接及手动全量刷新最多读取 10 页、每页 100 条会话元数据；定时同步读取最新一页，不扫描项目文件或完整聊天日志。只同步当前连接的服务；其他 SSH 主机需连接后再发现。
- 项目标题打开该项目；左侧箭头折叠/展开，`⋯` 提供刷新会话、修改项目名、查看本地归档、移出列表。移出列表只改本机导航，远端文件、聊天及任务保留；移除的项目不会被定时发现自动加回，可手动再次添加。
- 会话右侧 `⋯`、右键或 Shift+F10 打开菜单：重命名、置顶/取消、本地归档/恢复、从已结束回合分叉。更多历史会话通过分页读取，按远端 ID 去重；迟到的旧页面不会覆盖较新的名称。
- 置顶和归档保存在本机项目列表配置。归档不是 `thread/archive`：官方接口会移动远端日志且可能归档后代，因此本轮选择本地整理，运行任务继续。查看归档可恢复到普通列表；远端已归档目录的浏览/恢复不属于本轮功能。
- 重命名调用官方 `thread/name/set`，读回确认。分叉从最近已结束的回合复制历史，传 `lastTurnId`、`excludeTurns` 和 `deferGoalContinuation`；只对新会话取得本机控制权，若复制目标处于 active，则将新会话目标暂停。原会话不恢复、不暂停、不改目标；没有已结束回合时提示稍后再分叉。

## 会话保护与恢复

- 同一 SSH/CLI/socket 的项目切换复用现有 RPC，保留已有会话的控制权和任务事件，只切换界面只读跟进器；不会 unsubscribe、resume 或 interrupt 原任务。切换至其他服务时重建本客户端传输，远端官方常驻继续。
- 切换前刷新本地草稿，切换后按原有 scope 恢复文字、引用、附件、计划模式与最近会话。跨项目打开已验证的根会话时转到其真实 cwd 对应项目，避免输入落入错误项目。子代理继续使用既有父会话导航。
- 连接/发送尚未完成时，项目切换会提示等待。项目操作期间禁止交错发送；取消或连接变化使旧操作不能在新连接继续执行。
- 后台列表同步只执行 `thread/list` 等元数据读取，不调用 `thread/resume`、`turn/start`、`turn/interrupt` 或归档。保留草稿、当前选择、置顶、归档、已加载的旧会话及分页游标；失败保留缓存，不要求断开重连。
- 本机配置位于 Application Support/RemoteCodex/Workspace/projects.json，目录 0700、文件 0600，带跨进程锁和原子更新。旧单项目设置首次迁移为一条项目记录；手动清空列表后不自动重新添加。
- 远端需提供 Python 3 用于目录创建/检查，Codex 入口需可用。取消创建选项时只接受已有目录；不自动安装远端组件。未接入项目拖拽排序、远端项目目录浏览器或会话删除。

## 实现

- `WorkspaceCatalog.swift`：项目记录、连接身份、目录归属、置顶/本地归档；`ThreadManagement` 校验来源并处理元数据重命名和安全分叉。
- `Coordinator.swift`：导航动作、同服务连接复用、分页游标/迟到隔离、草稿与选择恢复、根会话目录路由。
- `Connection.swift`：新分叉 ID 取得独立本机租约及计划快照配置；不为原会话取得租约。
- `Resources/projects.js`：项目组、菜单、表单、归档视图、分页、忙碌/错误反馈；`app.js` 接入现有会话/草稿显示。
- 公开界面模板为 `Design/app-template.html`，新增样式由 `scripts/sync-prototype.py` 生成。

接口参考：[官方 App Server](https://learn.chatgpt.com/docs/app-server)。具体字段核对远端 CLI 0.163.0 schema，包括延迟 fork 目标继续；没有引入 T3 代码。
