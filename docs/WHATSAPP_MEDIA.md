# WhatsApp 媒体与设备关联

更新：2026-10-26。

## 桌面使用

- 消息侧栏的“关联 WhatsApp”提供扫码和电话号码两种方式。手机号需包含国家区号；配对码在手机 WhatsApp 的已关联设备流程中输入。界面自动读取关联状态，关闭窗口不会退出账号。
- 明确点击开始关联后，远端会先备份旧 auth 目录，再初始化新设备登录；已连接账号不会被重置。请使用原 WhatsApp 账号重新关联，当前未提供多账号切换/历史分离功能。
- 账号密钥始终在远端。二维码、配对码和手机号只用于当前关联窗口，不写入草稿或应用日志；关闭窗口清除显示内容。成功连接会写远端自动连接标记，登出后移除标记。
- 新收到的图片、文件、视频、音频显示媒体卡片。点击加载图片/加载并播放按需下载，图片显示缩略图，音视频使用原生 WebKit 播放控件；不支持的编解码格式可打开系统预览或保存。
- “系统预览”使用 macOS Quick Look，“保存…”使用系统保存面板。
- WhatsApp 回复框左下 `+` 选择附件，也可拖入文件或粘贴图片。每条回复一个附件、单个最多 25 MiB。发送前明确确认当前联系人/群、文件名、大小和说明。音频带说明时按文件发送，避免丢失说明。
- “引用到 Codex”只处理当前一条消息：媒体实际下载、校验后加入当前 Codex 附件草稿，点击 Codex 发送后才上传到对应远端并交给模型。图片作为图片输入；音视频和普通文件通过远端文件路径供工具读取，不自动转录/转码。
- 回复文字与完成添加的附件按原草稿作用域恢复，发送失败保留；确认后只清本次附件，发送期间输入的新文字保留。未确认结果不自动重发；同一提交键不会重复发送。

## 边界与存储

- 原历史中的 `[图片]` 等只保存过文字，没有媒体源，无法仅凭占位恢复；界面会提示需从手机重新发送。此版本部署后新收取或平台重新同步的媒体才具有下载描述。
- 阅后即焚、已撤回或超过 25 MiB 的媒体不提供下载。过期、无法重新获取或校验失败时显示错误，不以占位符冒充实际文件。
- SQLite 增加独立 media 表，旧消息表不改变。消息查询/MCP 只返回媒体元数据；媒体加密描述保存在远端私有库，不传给 Mac。
- 远端缓存：`~/.local/state/remote-codex/media/<UUID>/content`；目录 0700、文件 0600。下载校验大小/SHA256；只接受 WhatsApp CDN 来源，不接受客户端任意路径或 URL。发送用服务器缓存 ID，由服务端核对收件人与文件摘要。
- 本机下载缓存位于私有临时目录，正常关闭客户端清除；草稿附件继续由 DraftStore 归档。远端媒体暂没有自动清理策略。
- 预览和引用不取得 Codex writer，不启动模型回合。关联只操作 WhatsApp worker；不重启 Codex 服务，不触碰原会话。

## API 与代码

- `POST /media/upload?conversation_id=...&name=...`：二进制上传，Content-Type 指明媒体类型。
- `GET /media/<UUID>`：按需下载并校验，返回 SHA256 头；保持 SSH 隧道与既有请求头限制。
- `POST /messages/send`：增加可选 mediaId，允许仅附件，仍需固定幂等键。
- `GET /whatsapp/auth`：当前关联状态与有效的临时挑战。
- `POST /whatsapp/auth`：`{mode:"qr"}` 或 `{mode:"phone",phoneNumber:"..."}`，仅由用户开始操作。
- `whatsapp/media.mjs`：有界流式下载、路径及来源限制、媒体发送内容。
- `whatsapp/auth.mjs`：手机号验证、旧资料备份、单实例关联锁、临时挑战。
- `gateway/media.py`：媒体索引与缓存、旧库兼容、摘要与收件人绑定。
- `Sources/RemoteCodex/MessageMedia.swift`：私有缓存、WebKit Range 播放和 Codex 附件导入。
- `Resources/message-media.js` / `whatsapp-link.js`：媒体与设备关联交互。

## 提及姓名显示

WhatsApp 正文、会话预览和 Codex 单条引用将已知联系人提及显示为 `@姓名`，正文和引用卡片使用浅色标签，悬停可看原始标识。远端原消息与草稿原文保持原样；实际提交给 Codex 的引用文字使用同一姓名格式。找不到可靠名称或身份存在歧义时保留原标识，不推断或跨平台匹配。
