# 自动重连与本地草稿恢复

更新：2026-10-27。继续使用已批准的 macOS 界面；Telegram 和系统通知功能未扩展，通知实测仍暂停。

## 连接恢复

- Codex 与消息通道各有一个 `ConnectionRecovery`，按 1、2、4、8、15、30 秒退避，之后以 30 秒为上限继续；一次只执行一个连接尝试。取消、设置变化与退出使旧尝试失效，迟到结果不能关闭新连接。
- 自动连接只调用 initialize、账号存在检查及会话/模型/目标/计划的读取路径。打开已选会话保持只读交互；已加载官方会话可用无配置覆盖的 resume 订阅实时观察（不加入 controlledThreads），未加载会话不 resume。不重放 send、turn/start、turn/interrupt、目标修改、! 命令或平台消息发送。
- 2026-10-27 起连接先复用已有官方常驻，两种标准入口都缺失才创建官方 app-server。手动关闭本客户端创建的空闲常驻后取消自动重连，远端标记也阻止普通重连自动创建；须显式“创建并连接”。不执行 systemctl。复用实例只断开本客户端；消息连接独立。
- 休眠时关闭本客户端自己的传输并保留草稿；唤醒后重建连接。真实物理休眠尚未人工验收，生命周期调用及恢复调度有测试覆盖。演示模式不注册真实连接恢复。
- 消息 SSH/WS 断线会重建通道、重读目录与当前会话；`resyncRequired` 也会补读。只能恢复服务端实际已保存的消息，不保证 WhatsApp 平台尚未推送的离线历史完整。
- WhatsApp 登录态与网络状态分开。账号登出时连接恢复仅检查健康、同步已有目录/记录，不执行配对、二维码登录或重建账号。用户告知设备可能已登出，本轮无需使用真实账号，未进行重新登录；后续需要真实账号时再检查登录流程。
- 远端查询繁忙可能超过单次 RPC 超时。真实验收首次在读取列表阶段超时，旧版诊断同样出现 thread/list 超时；未重启服务，后续只读重连通过。连接握手和请求超时也会影响总恢复时间。
- 会话列表和诊断使用 `thread/list.useStateDbOnly=true`，只读官方状态索引。模型/设置发现与初始列表并行，列表失败不关闭已建立的 SSH；项目侧栏显示“重试读取会话”，保留已有列表、分页游标和草稿。重试仅请求列表，不重新连接、不恢复写入会话。列表完整度依赖远端状态索引。

## 本地保存

- `DraftStore.swift` 保存到 `~/Library/Application Support/RemoteCodex/Drafts/<scope>/`；scope 是 SSH 主机、项目、官方服务逻辑入口、Codex 路径的摘要。自动发现保留旧默认逻辑入口，切换到标准官方常驻不会丢失已有草稿。
- 保存 Codex 输入、单条引用、计划模式、完成添加的附件/远端引用、消息回复和平台/联系人选择。输入变更约 180 ms 合并写入；正常退出/休眠尝试刷新队列，正常退出最多等待 3 秒。进程突然崩溃时最后尚未提交的输入可能来不及写入。
- 每次只更新一条草稿记录，跨进程文件锁与原子替换保护文件。未编辑窗口关闭不会覆盖其他窗口的新草稿；同一会话多个窗口主动编辑时以最后保存为准。
- 目录 0700、文件 0600，不保存账号令牌、SSH 私钥、问答卡片/审批答案或自动发送队列。内容是本地普通文件，未额外实现应用层加密。
- 附件先完成添加和校验，再复制到私有草稿目录。重开校验 SHA256 并恢复为可发送卡片；失败保留错误卡片供用户移除/重添。未完成的分块不作为完整附件恢复。发送确认/移除后的保存会清理不再被任何草稿引用的本地附件；远端已上传文件的保留策略不变。
- 发送确认仅清除对应旧草稿和附件，保留期间新输入。断线导致结果不明时保留并提示，自动重连绝不自动重发。WhatsApp 回复也保留发送期间的新输入。

## 代码导航

- `ConnectionRecovery.swift`：独立重连调度、退避和取消。
- `Coordinator.swift`：连接生命周期、只读恢复、消息补读、草稿校验/附件恢复/退出刷新。
- `Connection.swift` / `Gateway.swift`：旧连接结果隔离；消息 SSH 退出和 WS 断线处理。
- `DraftStore.swift` / `Attachments.swift`：私有原子保存、附件归档/校验/清理。
- `Resources/drafts.js`：按连接和会话保存、合并写入、恢复及失败提示；`app.js` / `commands.js` 接入编辑与确认事件。
